Scratch pad

Pi 400 — fresh Debian 13, booting from USB

Pi 400 rev 1 — that's a Pi 4 underneath, so USB boot is built in. You don't even need to touch the EEPROM.

One thing you do need: a USB stick or SSD. There is no way to write a fresh image onto the disk you're currently booted from — the running root filesystem is on that card. A 16–32 GB stick costs a few euros; a USB 3.0 SSD is the better long-term answer, since the Pi 400 has USB 3.0 ports and it'll be dramatically faster than the SD.

1. Grab the image (on the Pi)

Latest is Debian 13 "Trixie", 6 Oct 2026. Lite (no desktop, 525 MB): 

mkdir -p /tmp/newsys && cd /tmp/newsys
wget https://downloads.raspberrypi.com/raspios_lite_arm64/images/raspios_lite_arm64-2026-10-06/2026-10-06-raspios-trixie-arm64-lite.img.xz
wget https://downloads.raspberrypi.com/raspios_lite_arm64/images/raspios_lite_arm64-2026-10-06/2026-10-06-raspios-trixie-arm64-lite.img.xz.sha256
sha256sum -c 2026-10-06-raspios-trixie-arm64-lite.img.xz.sha256

Want the desktop? Same directory, swap raspios_lite_arm64 → raspios_arm64 and drop -lite (check the exact filename on the downloads page).

2. Plug in the USB drive and verify the target

lsblk -o NAME,SIZE,MODEL,TRAN,MOUNTPOINT

You want a new /dev/sda with TRAN=usb. /dev/mmcblk0 must never appear in the next command — that's your 64 GB card.

3. Write it

xz -dc 2026-10-06-raspios-trixie-arm64-lite.img.xz \
  | sudo dd of=/dev/sda bs=4M conv=fsync status=progress
sync

4. Pre-seed SSH so it boots headless

sudo partprobe /dev/sda
sudo mkdir -p /mnt/boot && sudo mount /dev/sda1 /mnt/boot
sudo touch /mnt/boot/ssh
printf 'pi:%s\n' "$(openssl passwd -6 'your-password')" | sudo tee /mnt/boot/userconf.txt
sync && sudo umount /mnt/boot

SSH is off by default on a fresh Trixie, so that ssh file is what saves you from needing a monitor.

5. Boot from it

sudo poweroff

Unplug the power, pop the microSD out (slot on the edge of the case), plug the Pi 400 back in with the USB drive attached. Default boot order is 0xf41 = SD then USB, so with the card out it goes straight to USB.

Verify afterwards: vcgencmd bootloader_config | grep BOOT_ORDER and findmnt / should show /dev/sda2.

6. Decide where it lives

Option A — stay on USB (recommended)

Faster, and your 64 GB card stays in a drawer as a working rollback. Nothing else to do.

Option B — clone the new system onto the 64 GB card

While booted from USB, the card is idle, so you can write to it: 

lsblk -o NAME,SIZE,TRAN,MOUNTPOINT     # confirm mmcblk0 is present and unmounted
xz -dc /tmp/newsys/2026-10-06-raspios-trixie-arm64-lite.img.xz \
  | sudo dd of=/dev/mmcblk0 bs=4M conv=fsync status=progress
sync
sudo poweroff

Remove the USB drive, put the card back, boot. The rootfs auto-expands to fill 64 GB on first boot, so no raspi-config resize dance needed.

If you want both drives in at once later, set BOOT_ORDER=0xf14 (USB first) via sudo rpi-eeprom-config --edit.

If you genuinely have no spare USB storage

Then a clean install isn't possible without some second medium, and your options collapse to:

  • In-place upgrade, Buster → Bullseye → Bookworm → Trixie, via legacy.raspbian.org. Each hop can kill networking (dhcpcd → NetworkManager) or booting (/boot → /boot/firmware), and any failure leaves you with a non-booting Pi and no way to fix it. On a custom Amiga image, I'd put the odds below 50%.
  • Network boot over the Ethernet port with a TFTP server on your LAN. Clean, but a lot of setup for something a €7 stick solves.

Given the Pi 400's USB 3.0 ports, honestly the stick/SSD is the upgrade: you go from an EOL Buster image to current Trixie, keep the old card intact, and end up with a faster machine.
